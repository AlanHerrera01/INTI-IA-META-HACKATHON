## Main post — English

What can a local agent actually do — and prove?

That was my question during the Meta Global AI Developer Hackathon 2026. I built INTI AI around it: a local-first desktop agent that connects a bilingual dashboard to a Windows PC.

Here is what INTI can do:

→ Pair a computer with a one-time code, inspect installed apps, and grant or revoke per-device permissions.
→ Turn an allowlisted web screen into a typed scene of elements and UI state with Meta Muse Spark.
→ Convert a goal and its constraints into a typed plan with ordered actions, targets, preconditions, expected results and risk levels. Unsafe proposals are rejected.
→ Hold execution until the operator approves the exact plan by SHA-256 digest, with a separate confirmation for high-risk actions.
→ Run approved actions in the synthetic Chromium inventory app, or on the PC: create and read back text files, ask Notepad to open a file, open an approved URL, or launch an authorized application.
→ Generate a quotation dossier in a fresh folder — Word, Excel with formulas and a native chart, print-ready PDF, text summary and SHA-256 manifest — then reopen it and check fields, totals, structure and hashes.
→ Diagnose a failed execution with a bounded repair plan that requires fresh approval and never replays actions automatically.
→ Verify sandbox outcomes independently: persisted state, explicit criteria, hash-checked evidence, and a verdict with JSON/HTML reports.
→ Show measured latency, throughput and verification results, and leave unavailable metrics blank.

What it does not do: no shell, no deletion, no arbitrary executable, no signing or sending, and no writes outside the approved folder. Desktop screenshot capture and automatic model calls are not implemented or disabled by default.

That last part matters as much as the list above. A capability you cannot inspect is not trust; it is marketing.

## Main post — Español

¿Qué puede hacer de verdad un agente local — y qué puede demostrar?

Esa fue mi pregunta durante el Meta Global AI Developer Hackathon 2026. Construí INTI AI alrededor de ella: un agente de escritorio local que conecta un dashboard bilingüe con una PC Windows.

Esto es lo que INTI puede hacer:

→ Emparejar una computadora con un código de un solo uso, inspeccionar las apps instaladas y otorgar o revocar permisos por dispositivo.
→ Convertir una pantalla web permitida en una escena tipada de elementos y estado de UI con Meta Muse Spark.
→ Transformar un objetivo y sus restricciones en un plan tipado con acciones ordenadas, objetivos, precondiciones, resultados esperados y niveles de riesgo. Las propuestas inseguras se rechazan.
→ Bloquear la ejecución hasta que el operador apruebe el plan exacto por digest SHA-256, con confirmación separada para acciones de alto riesgo.
→ Ejecutar acciones aprobadas en la app sintética de inventario en Chromium, o en la PC: crear y releer archivos de texto, pedir a Notepad que abra un archivo, abrir una URL aprobada o lanzar una aplicación autorizada.
→ Generar un dossier de cotización en una carpeta nueva — Word, Excel con fórmulas y gráfico nativo, PDF listo para imprimir, resumen y manifiesto SHA-256 — y después reabrirlo para comprobar campos, totales, estructura y hashes.
→ Diagnosticar una ejecución fallida con un plan de reparación acotado que exige nueva aprobación y nunca repite acciones automáticamente.
→ Verificar resultados del sandbox de forma independiente: estado persistido, criterios explícitos, evidencia con hashes y un veredicto con reportes JSON/HTML.
→ Mostrar latencia, throughput y resultados de verificación medidos; las métricas no disponibles quedan vacías.

Lo que no hace: no tiene shell, borrado, ejecutables arbitrarios, firma ni envío, y no escribe fuera de la carpeta aprobada. La captura de escritorio y las llamadas automáticas al modelo no están implementadas o están desactivadas por defecto.

Esa última parte importa tanto como la lista. Una capacidad que no puedes inspeccionar no es confianza: es marketing.
